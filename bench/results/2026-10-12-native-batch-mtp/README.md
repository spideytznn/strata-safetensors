# 原生双路 MTP：2026-10-12 本机验收

复用官方 batch slot verifier，让两个 safetensors 请求都使用原生 MTP。
一份原始 BF16/F32 与 FP8 草稿权重、完整输出头由各路共享；草稿 KV、激活、
图输入和图片位置独立。并发每路最多一枚草稿，置信度不足时该路只验证一行目标。
主模型继续验证、回滚和提交；未改变目标权重、量化、专家路由或算术内核。

硬件为 RTX 5090（驱动报告 32607 MiB）、Ryzen 9950X3D、96 GB RAM，
Windows，NVIDIA 驱动 617.14，CUDA 13 / SM120 构建。
详细配置、二进制与源码 SHA256、测试分支、原始记录路径见 [summary.json](summary.json)。

## 同日吞吐对照

262144 上下文、4096 行专用 prefill、INT8 KV、GPU 视觉先加载、8 GiB 会话缓存、
相同初始专家 profile 的独立副本、热专家晋升、PCIe fraction 0.25。
温度 0.7、思考模式、top_p 0.95、top_k 20、seed 9950。
各组保留一次预热与两次重复，表中为重复中位数；每路生成 256 token。
双路合计用实际输出的 512 token 除以墙钟时间，包括两次 admission，
不使用引擎 verify-row 计数作为输出吞吐。

| 请求对 | 不加载 MTP | 共享原生 MTP | 提升 |
|---|---:|---:|---:|
| 短文本 | 81.24 tok/s | 91.05 tok/s | 12.1% |
| 代码 | 81.69 tok/s | 93.43 tok/s | 14.4% |
| 8K 文档缓存重复 | 81.59 tok/s | 90.39 tok/s | 10.8% |

两路均开始输出后的合计吞吐分别为 85.43→96.34、86.44→99.49、86.30→96.89 tok/s。
8K 文档首次请求包含 prefill 的总吞吐为 42.00→42.04 tok/s，基本持平。
另一次贪心模式筛选比较了关闭 MTP、串行草稿和异步草稿；
异步草稿没有明确的额外收益，故 `STRATA_NATIVE_BATCH_MTP_ASYNC=1` 仅为显式选项。
各次筛选均逐 token 检查跨模式及重复输出相同。

原始记录位于本机 `bench/results/local-native-batch-mtp-20261012-bench/`
和 `local-native-batch-mtp-20261012-thinking-bench/`。第二次调换了关闭 MTP 与
串行草稿的运行顺序，并切换到日常采样。两次筛选不能混为同一采样条件。

## 正确性与缓存

- 原生 GEN/BGEN 回归通过贪心、固定种子、重复惩罚、逐请求置信度混合、
  严格阈值、取消恢复、续聊、长度限制、EOS，以及 18979 token 长槽扩容/替换/恢复。
  观察到两路的 1+1、1+2、2+2 验证行布局。
- 回归记录到 92 轮真实多槽晋升、8516 次专家晋升；用 `active_slots=2`
  区分两路活跃与单路两行，避免把单路 MTP 行误算为并发晋升。
- 异步草稿的扩展带图测试通过 31 个请求，包括 141098/126147 token 不同图片位置/
  网格、历史图片续聊、长 prefill 让位后恢复。27 个完整且非取消相关的输出
  与此前 target-only 带图验收逐 token 一致。
- 最终默认串行草稿程序、最终桌面配置再通过 22 个带图请求，涵盖图/图、图/文、
  固定种子、历史图片复用、替换图片隔离和取消恢复，退出码为 0。
- 所有列入验收的模型进程，在驻留后专家与 MTP 源读取计数均为 0；ngram 按需读取仍保留。
- 9 项服务测试、4 项 CTest、Python 编译检查和 `git diff --check` 通过。

## 使用与边界

现有桌面双路入口指向 `strata-native-batch-mtp-final.exe`，选择
`--mtp native --batch-mtp --spec 3 --spec-min-p 0.5`。
独立 KV、设备槽复制、图片缓存、8 GiB 会话缓存、热专家晋升和现有 host/端口设置保留。
并发每路最多一枚草稿；单独运行时仍可按 spec 3 验证最多两枚草稿。
通用引擎/配置生成器的默认路径未启用 MTP；本机双路配置是显式选择。
旧 `strata-vision-cache.exe` 与本轮前的配置副本保留在本机供回退。
没有推送远端，没有启动 HTTP 服务。

日常参数对照中，热专家缓存由 13008 MiB 降为 10270 MiB，约减少 2.7 GiB；
所有专家仍常驻锁定 RAM。低置信度的窗口仍计算下一枚草稿以获得下一次置信度，
尚无按实时收益自动卸载 MTP 的策略。
这里只测了有限提示、两次预热重复和列出的上下文，不能据此保证其他任务更快或全面质量相同。
没有冷 prefill 提速承诺，也没有 HIP、SYCL、Linux 或多 GPU 验证。
